# The three controls

## 1. The brief — *Start a new video*, Finishes

A numbered switch row named exactly **Source watermark**, on by default, in the
same list as Captions, Opening title, Chapter cards, End screen, Sound effects,
Drawn cards and Music (`FINISHES` in `platform/app/new/page.tsx`).

- **on** — "Show a small label indicating whether each visual is AI-generated,
  authentic, archival, or illustrative."
- **off** — "No origin label on screen — the provenance is still recorded, and a
  credit a licence requires is still shown"

**It is the one finish the SITE stores rather than the orchestrator's
`Normalize Webhook Input`.** Deliberate: the setting has exactly one reader (the
`Source Watermark` node in Final Assembly, which reads Editing Options directly)
and two writers, both on the site — this form and Final touches. Final touches
already writes it through `updateEditingOptions`, so the brief uses the same
writer and the key has one write path instead of two, in two languages, that
would have to agree about what absence means.

`createProject` writes `{ sourceWatermark: false }` **only when the producer
refused it**, after the project record is confirmed and before the redirect.
`updateEditingOptions` merges, so it cannot disturb what the orchestrator has
just written. A failure there leaves the watermark on, which is the safe
direction.

## 2. Final touches

The same switch, as a row in `FinalSettings.tsx`'s `OPTIONS`, initialised from
the project's stored value and sent with the confirm — like `sfxLevel` and
unlike `speed`, because this panel *displays* it, so writing it back is a no-op
unless the producer moved it.

The renderer always uses the latest saved value: `Source Watermark` in Final
Assembly reads Editing Options at render time, not at confirm time.

## 3. Footage type — per scene, Documentary only

`FootageTypePicker`, in the Inspector on the **Images** step. Documentary only,
because every other category is AI end to end and a control with one possible
answer reads as a decision nobody has to make.

It shows what the record currently says — the badge, the creator or provider,
the source title, the confidence, whether a person set it, and a link to the
source page — then a select of all eight types, a one-line description of the
chosen one, and (for a real origin) three optional fields: **what event**,
**where**, **when**.

Two moves are **refused**, not confirmed:

- **An AI picture may not be relabelled as real of any kind.** The message is
  the specification's own sentence — *"This visual was generated by AI. It
  cannot be marked as authentic footage unless the underlying media source has
  been replaced."* — plus the door: pick an archive asset from the panel under
  the picture, and it carries its own provenance. A confirmation dialog cannot
  make an AI picture authentic, so there is no confirmation dialog.
- **A real archive picture may not be relabelled as AI**, with "Back to AI" named
  as the way to do it properly.

All eight options are still *offered* on every scene. A producer has to be able
to see that ACTUAL FOOTAGE exists and be told why this scene cannot be it; a
control that silently has fewer options on some scenes explains nothing.

Choosing any type **pins** it (`manuallyVerified`), or the next image approval
would quietly re-classify the scene and the answer would vanish. **Automatic**
releases the pin.

Nothing about the three optional fields is pre-filled from the archive's own
date. That field is frequently the upload date, and pre-filling it would put a
guess on screen under the producer's name.
