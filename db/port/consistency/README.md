## What the producer asked for, and what was built

Two systems, both asked for on 2026-09-08 after the long film showed the same
character with a different face from one scene to the next and the same
building rebuilt differently every time it was reused:

1. **A character sheet made BEFORE the first image** — front, back and both
   profiles, in the character's outfit — attached as a reference to every
   scene the character is in.
2. **Each unique place gets an exact description**, always included when the
   place is reused.

Both were taken further than asked, because a description is a hope and a
picture is an anchor (this repo's oldest lesson, "an instruction in a prompt
is not a constraint"):

| Piece | Where | What |
|---|---|---|
| **Turnaround sheets, by tier** | MG `Load Scene Cast → Cast Sheet Prep → Cast Sheet? → Generate Cast Sheet → Collect Cast Refs → Save Cast Refs` | A LEAD (in ≥ max(3, 10%) of scenes, or the protagonist with ≥ 2) gets a four-view turnaround (front, left profile, back, right profile, neutral grey backdrop, 16:9); a RECURRING character (≥ 2 scenes) the single portrait the cast-sheet port already made; a one-scene extra nothing. A portrait is upgraded to a turnaround when a character qualifies on a later pass. Cap 6. |
| **The producer's photo is the protagonist's sheet** | `Cast Sheet Prep` | When the film has `refImageMediaId`, the protagonist's turnaround is drawn FROM it (`reference_1`, GROUND TRUTH wording), so the real face reaches every scene, not only the hook. |
| **Hero object sheets** | same chain, `bible.objects` | The bible now lists OBJECTS (a car, a machine, a boat). One in ≥ 2 scenes gets a three-view product sheet. Cap 3. On the race film the CAR was the character that drifted. |

## What bites

- **`Editing Options` gained four keys**, all merged with `||` never rewritten:
  `castSheets {name: {id, url, kind}}` (kind is `turnaround` or `portrait`),
  `objectRefs {name: id}`, `locationRefs {name: id}`, `locationPlates {name:
  {id, url}}`. `castRefs {name: id}` stays as it was and is what the
  assembler reads; `castSheets` is what decides the tier and what the judge
  looks at.
- **The sheets' `fifeUrl` dies in about six hours.** The Flow media id lives
  forever and is what generation uses, so consistency is unaffected — but the
  JUDGE needs a URL it can show a vision model, so on a pass that starts more
  than ~6 h after the sheets were made, `Judge Prep` finds every URL expired,
  emits `skip`, and the frame ships unjudged with `JUDGE skipped` in the log.
  The fix, when it matters, is to re-host the sheets through
  `/api/media/ingest` like a scene image; not done here because sheets are not
  scene assets and the ingest endpoint is keyed by scene.
- **`Load Scene Cast` reads the film's APPROVED scenes before the sheets are
  planned**, so tiers are decided on the whole film, not on the batch. It is
  `alwaysOutputData` so a film with no rows still reaches `Cast Sheet Prep`
  (which filters empty items) rather than ending the pass in silence — the
  `Cast Sheet Prep never returns zero items` rule, one node earlier.
- **`Generate Set Plate` and `Consistency Judge` cannot kill the batch.** Plate:
  `continueRegularOutput` + `alwaysOutputData`, and `Collect Set Plates` logs
  `SET PLATE FAILED: <name>` and leaves that location on text alone. Judge:
  3 retries × 5 s, then `continueRegularOutput`; `Judge Verdict` reads an
  unreadable answer as a pass. Neither is worth a dead film.
- **A re-roll goes back through `Needs Image?`**, with the scene re-read from
  the database (`CONS Reload Scene`) so `Build Image Request` runs again for
  the same scene, reads `sd.consistencyRerolls[sceneId]` and switches to
  STRICT MATCH. The discarded frame is never written: `Write Scene Image` is
  only reached on `If Reroll?`'s false branch. Same re-entry pattern as
  `IMG Reload Scene` (refusals) and `VP Reload Scene` (video filter).
- **Two sheets is the cap per shot, and the photo counts as one.** A third
  sheet crowds the composition (measured on the cast-sheet port). With five
  reference slots the previous frame is dropped first, then nothing else —
  the order above is the priority order.
- **Tags decide presence; `Prompt Vizual` is only the fallback.** A film whose
  scenes carry `char:` / `loc:` tags is matched exactly; one that predates the
  tags is matched by name in `Prompt Vizual`, with the cast-sheet port's rule
  that a shared surname is not an identifier. A scene whose tags exist but
  name nobody gets no cast sheet — that is the segmenter's decision, not a
  miss.
- **`time_of_day` is stored (`tod:`) and not yet read by any generator.** It
  is there so the plate's "light follows the text" instruction can one day
  become a per-scene lighting clause; today it is a tag.
- **Hardcoded useapi bearer on `Generate Set Plate`**, exactly like
  `Generate Cast Sheet` and the three image generators — same rotation cost,
  same export leak, listed in the CLAUDE.md key-rotation note.

**One thing the run showed and the fix that followed** (Media Generation
`3fd53a5f`, Claude Scripting `5ab94af7`, `applied/03-*` and `04-*`): the
sheet prompt, the assembler's cast sentence and the judge's questions all said
"ONE person", "face, hair", "natural skin texture" — written for humans and
wrong for a snail and a turtle, or any non-human cast. Now "ONE character (a
person, an animal or a creature, exactly as described)", "face or head, hair
or markings, colours", "skin or surface texture". Same assembler in all three
places, re-diffed and republished.
